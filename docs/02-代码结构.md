## 一、总体数据流

```
                    ┌─────────────────── 车机本机环回 ───────────────────┐
                    │ 迪加 HTTP :8988  迪加遥测 SQLite  迪友无障碍文本     │
                    └───────┬──────────────┬───────────────┬────────────┘
                            │              │               │
   BYD 统计设备(部分可读) ──┼──────────────┼───────────────┼──→ VehicleData（静态单例）
                            │              │               │        │
  YBAdb shell  ────────────┴── screencap -d 1 ──→ NavProbe ──→ NavState │
                                                  （像素判定）          │
  通知监听 ──→ MediaListener（封面/进度/时长）                            │
  网络 ──→ LyricLoader（四级回退歌词）                                   │
                                                                        ▼
                                                    CardActivity.CardView.onDraw()
                                                    ├─ 静态层缓存（油耗/胎压）
                                                    └─ 每帧层（封面/歌词/进度条）
                                                                        ▼
                                                          display 1 · 1920×720
```

`/sdcard/clusterlab_style.txt` → `Style`（每 2s 重读）→ 所有绘制都过 `Style.size/color/alpha/weight/stroke*`。

### 2.2 每帧绘制顺序（`onDraw` → `drawStatic` / `drawDisc` / `drawLyrics`）

1. 导航状态变化 → 记日志，重建静态层
2. `VehicleData.refresh()`（内部有节流）
3. `resolveNight()`（1.5s 节流；文件优先，其次 `Configuration.uiMode`）
4. `ensureStatic()`：缓存层（油耗 + 胎压），只在样式版本/主题变化时重建
5. 画静态层（有 clip 时局部 blit，省 CPU）
6. 大窗额外画旋转唱片 `drawDisc`
7. `drawLyrics()`：大窗 6 句 / 小窗 4 句，长句自动换行（v3 起无进度条）

### 2.3 歌词块算法（最容易踩坑的地方）

```
idx      = indexAt(effPos)                     // 当前唱到第几句
maxK     = 6 - aboveLines - 1 = 4              // 当前行下面还能放 4 行
baseIdx  = min(idx, lastIdx - maxK)            // 贴末尾就钳住，保证永远 6 行
atTail   = baseIdx != idx                      // 已在末尾 → progress 归 0，不再滚动
baseY    = BIG_LYRIC_TOP + aboveLines*lineH + lcur字号
每行 y    = baseY + k*lineH + (k>=1 ? curExtra : 0)   // curExtra 现在恒 0
```

- **所有行 `setMaxLines(1) + TruncateAt.END`** —— 单行是硬约束，换行会撑破行高。
- 字号按 `k` 给：`k=-1` → `lprev`，`k=0` → `lcur`，其余 → `lfar`。
- 颜色按"这一句是不是当前句"给（末尾不滚时高亮仍逐行走）。
- 上界 `topLimit = BIG_LYRIC_TOP - 6`（避免压到上方内容），下界 `y + curExtra > SB - 6` 裁掉。

### 2.4 油耗优先级（`VehicleData.pollStats`）

```
1. pollFuelDb(ctx)      /sdcard/vandiplus/db/vehicle_telemetry.db 里「最近 50km」分段：
                        sum(fuelDelta) / sum(distance) * 100，电耗同法
2. pollCurrentTrip()    GET /api/currentTrip（迪加本次行程），dist < 0.5km 跳过
3. 都取不到             保留上次显示值（不做任何猜测回填）
```

`totalPHM = fuelPHM + elecPHM / KWH_PER_L`（`KWH_PER_L = 3.5`，等效换算，不是热值）。

> **v4.9.3 变更**：删掉「迪加百公里电耗」这一档。它给的是瞬时值（实测 49.3，而最近 50km 口径是 15.9），
> 两个量级来回切就是用户看到的「油耗一直跳动」；而且那个值只有电、不含油。

### 2.5 导航识别（`NavProbe.sample`，周期 ~240ms）

| 判定 | 区域 | 依据 | 阈值 |
|---|---|---|---|
| 是否在导航 | x 200~540 / y **172~196** | 卡片顶部是深色底（音乐窗口到不了这里） | 深色占比 ≥ **50%** |
| 大卡 vs 小卡 | x 200~540 / y **328~338** | 导航蓝条 `b>150 && b-r>60 && 80<g<180` 占比 | ≥ **30%** = 大卡 |

- 截图命令：`screencap -d 1 /data/local/tmp/.nav_probe.raw`（raw 比 PNG 快一倍，200ms vs 500ms）
- 只按 `y` 读需要的两段行，`dataStart = len - w*h*4` 直接定位像素区，不整图解压
- 切换手感：进入导航 1 次确认（240ms），退出 3 次确认（720ms）

### 2.6 启动链（`BootReceiver` + `KeepAlive`）

`BOOT / QUICKBOOT / SCREEN_ON / USER_PRESENT / TICK` 任一到达：

`BOOT` 与 `TICK` 都先排下一次精确闹钟（`AlarmKeeper`），再判断该不该拉界面：

1. 黑屏（`PowerManager.isInteractive()==false`）→ 只留闹钟，不动界面；
2. 心跳新鲜（`KeepAlive.beatAge() < 30s`）→ 认为卡片活着，忽略；
3. 否则 `am start-activity --display 1 -n com.byd.clusterlab/.CardActivity`（走 adb shell，uid 2000）。

`KeepAlive`（跑在 `:keep` 独立进程）每 3 秒：

- `YBAdb.exec(dumpsys window windows | awk ... isVisible)` 判可见；
- 连续两次不可见（约 6 秒）→ 重拉一次，随后重绑通知监听。

> 第三方 App 本地 `startActivity` **不能**跨屏：实测日志 `local_launch 落到 display 0，退出`，
> display 1 只能走 adb shell 的 `am start-activity --display 1`。这也解释了为什么开机前 25 秒不检查。
> 历史教训：`--activity-clear-task` 反复重开会带来侧滑入场动画（用户看到「一直跳动」），已弃用。

## 五、提权链（v4.0 起自研 ADB，两个包都不依赖 Shizuku）

两层，只做一件事：在 App 内自己拿到 uid 2000 的 shell，然后用它补权限、拉界面。

```
① AdbCrypto   本机 RSA-2048 + 三行密钥（PKCS8 / 模数 n / 指数 e）
                 ↓
② YBAdb       连 127.0.0.1:5555，手写 ADB 协议 + AUTH 签名，拿到 shell 流
                 ↓ exec(...)
③ YBPrivilege pm grant WRITE_SECURE_SETTINGS 等 / appops SYSTEM_ALERT_WINDOW /
                 cmd notification allow_listener / settings put secure
```

**ADB 协议要点**：
- 报文头 24 字节 = 6 个 little-endian uint32：command / arg0 / arg1 / data_length / data_crc32(填 0) / magic(command^0xFFFFFFFF)。
- 命令字：CNXN 0x4e584e43 / AUTH 0x48545541 / OPEN 0x4e45504f / OKAY 0x59414b4f / WRTE 0x45545257 / CLSE 0x45534c43。
- **签 token 是坑**：adbd 把 20 字节 token 当成已算好的 SHA-1 摘要，要签 3021300906052b0e03021a05000414 || token 的裸 RSA 私钥运算，不能用 SHA1withRSA。
- **只认自己那条流**：exec0 按 arg1（对端 remote id = 本端 local id）过滤报文，否则会把别的通道漏出的 WRTE 拼进结果（实测 TOP 查询收到过 settings get secure ... 的返回值）。
- **用完即断**：exec0 的 finally 里 if (--ops == 0) closeQuietly()，不常驻占 adbd 待授权槽；另有 45 秒 reaper 兜底，连续失败才指数退避（0→60s，成功归零）。

> 历史包袱：YBDaemon / YBCore / YBByd / YBFeed 那条「d_service 特权进程 + /sdcard 文件回传」的路在 v4.9.1 全删了 —— 实测 uid 2000 也没有 BYDAUTO_*_GET，读不到车况。
