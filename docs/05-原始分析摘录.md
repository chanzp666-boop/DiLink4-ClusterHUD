## 一、仪表屏到底是什么

| 项 | 值 |
|---|---|
| Display ID | **1**（中控是 0） |
| 分辨率 / density | 1920×720 / 320 |
| Surface 名 | `fission_bg_xdjaVirtualSurface` |
| 宿主进程 | `com.xdja.containerservice` |
| 硬件 | 高通 8155 上的**虚拟显示**，本质就是一个 Android display |

融合图：

```
仪表物理屏
 ├─ BydClusterQt（Qt/QML 主程序）
 │   ├─ 顶栏（P档/车速/时间）
 │   ├─ ADAS 3D 场景（Qt Quick 3D）
 │   ├─ 底栏
 │   └─ AndroidNativeWindow  ← 我们的 Activity 就嵌在这里
 └─ Android 层（display 1）
```

**结论**：因为是普通 Android display，所以能直接 `am start-activity --display 1` 往上投 Activity，
不需要 root，也不需要改 system。

## 二、启动与权限

```bash
# adb 里可以直接用
adb shell "am start-activity --display 1 -n com.byd.clusterlab/.CardActivity"
```

**App 内部**调用同样的 `am` 会失败：

```
SecurityException: Permission Denial: startActivityAsUser asks to run as user -2
  but is calling from uid u0a83; this requires
  android.permission.INTERACT_ACROSS_USERS_FULL
```

→ 这就是必须上 Shizuku 的根本原因（普通 App 没有 `INTERACT_ACROSS_USERS_FULL`）。

## 三、透明叠加的三个必要条件（缺一就黑屏/发灰）

```java
// 1. 窗口格式必须是 TRANSLUCENT（不是 OPAQUE）
lp.format = PixelFormat.TRANSLUCENT;
lp.alpha = 1.0f;

// 2. 背景必须透明 + 去掉变暗
getWindow().setBackgroundDrawable(new ColorDrawable(0x00000000));
getWindow().clearFlags(WindowManager.LayoutParams.FLAG_DIM_BEHIND);

// 3. 自定义主题，避免 NoTitleBar.Fullscreen 自带的不透明底
<style name="OverlayTheme" parent="@android:style/Theme.NoTitleBar.Fullscreen">
    <item name="android:windowBackground">@android:color/transparent</item>
    <item name="android:windowIsTranslucent">true</item>
    <item name="android:backgroundDimEnabled">false</item>
</style>
```

| 现象 | 原因 |
|---|---|
| 所有颜色被冲淡成浅灰 | `format=OPAQUE` 却画透明内容 |
| 背景全黑、地图透不出来 | 主题自带不透明 `windowBackground` |
| 封面发灰 | 复用 `fill` Paint，残留上一帧 alpha |

## 四、Shizuku 集成踩坑链（照抄即可）

| 阶段 | 现象 | 原因 | 解决 |
|---|---|---|---|
| 1 | `NoClassDefFoundError: IShizukuApplication$Stub` | 缺 `aidl` 包 | 加 `dev.rikka.shizuku:aidl:13.1.5` |
| 2 | `BootstrapMethodError` | `dx` 不支持 lambda desugar | 改用 **`d8`**（build-tools 33） |
| 3 | `binder haven't been received` | 没主动请求 binder | `ShizukuProvider.requestBinderForNonProviderProcess(ctx)` |
| 4 | `pingBinder()` 仍 false | **缺权限声明** | manifest 加 `<uses-permission android:name="moe.shizuku.manager.permission.API_V23" />` |

**第 4 条是决定性的**：Shizuku 主应用的 provider 受该自定义权限保护，
没申请时 `call` 被静默拒绝，**不抛任何异常**，只看日志会以为是 binder 没到。

## 五、保活与"被杀"的实证

```
ActivityManager: Force stopping com.byd.clusterlab: quickboot
ActivityManager: Killing 640:com.byd.clusterlab/u0a83 (adj 250)
```

BYD 的 `quickboot` 会在场景切换时**强制 stop 第三方 Activity**，前台服务挡不住显式 force stop。
→ 所以必须做**外部守护**（`com.byd.clusterassist` 的 Watchdog），而不是指望自己的 Service 活着。

```bash
# 电池优化白名单（仍然建议加）
adb shell "cmd deviceidle whitelist +com.byd.clusterlab"
```

## 六、进度推算（歌词"慢半拍"的经典坑）

```java
long raw = st.getPosition();
long adjusted = raw;
if (playing && speed > 0) {
    long d = nowRt - st.getLastPositionUpdateTime();
    if (d > 0) adjusted = raw + (long)(d * speed);   // 补齐到此刻
}
basePosition = adjusted;   // 必须用补齐后的值当基准
baseTime = nowRt;
```

错误做法是把**未补齐**的原始值当基准 → 每轮轮询都落后一个上报周期（300~500ms）→ 歌词永远慢半拍。

## 七、深浅模式判定

```java
int mode = Settings.Secure.getInt(resolver, "ui_night_mode", 2);
nightMode = (mode != 1);
```

- 每 1.5s 刷新
- **`persist.sys.byd.theme` 不能用作判据**（切换主题时恒为 `10000018`，不变）
- 更可靠的是 `Resources.getConfiguration().uiMode & UI_MODE_NIGHT_MASK`，两者不一致时以 Configuration 为准

## 八、ADAS 缩小（未做，参数已备齐）

ADAS 大小由 `naviType` 决定（QML 里 `DataSource.naviType === 4`）。
本车是 CanFD，所以：

| 操作 | device | event |
|---|---|---|
| 读 | `1007` | `1086337074` |
| 写 | `1007` | `1276157976` |

走迪加 Lua 通道：

```lua
local cur  = di.byd.getInt(1007, 1086337074)          -- 读当前 naviType
local code = di.byd.setInt(1007, 1276157976, 4)       -- 写；0=成功，-2147482644=权限拒绝
```

`di.byd.setInt` 通道已在座椅项目（`device=1023, event=1276186686`）实测成功，方法完全一致。
→ **不需要替换 `centerchild.cpp`**（它编译进 `BydClusterQt` 主二进制，替换等于重刷 system 分区）。

## 九、油耗口径的演进（重要背景）

| 阶段 | 口径 | 结果 |
|---|---|---|
| 最初 | 迪加 `tripStatistics`：`fuelDelta / distanceKm × 100` | 分母 1.5km、分子 0.1L 刻度 → 误差 ±6.7 L/100km，数值夸张 |
| 二阶段 | 累计寄存器（总电耗/总燃油/里程值）+ **50km 滚动窗口** | 误差 ±0.2，但更新慢 |
| 三阶段 | 先验收缩：`PRIOR_KM=5`，跨度越大越信窗口值 | 0.3km 就能出数 |
| **现状** | **迪友「最近能耗」无障碍文本**（迪友自己算好了） | 最贴近仪表，但通道会掉（问题 #1） |

单位换算：`综合 = 电耗 / 3.5 + 油耗`（3.5 kWh ≈ 1L 汽油，等效换算，不是热值）。
